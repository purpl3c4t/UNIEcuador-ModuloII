# 1.1 Fundamentos de UEBA y LoTL 
---
## Ejecución de la simulación de autoencoder profundo para UEBA
Esta guía explica cómo configurar el entorno y ejecutar el script de simulación de **Análisis de Comportamiento de Usuarios y Entidades (UEBA)** basado en PyTorch y adjunto en la carpeta de *Modulo 1* (`ueba-autoencoder-simulation.py`).

El script demuestra cómo un **autoencoder profundo subcompleto** (*under-complete deep autoencoder*) puede establecer una línea base de comportamiento utilizando telemetría empresarial normal y detectar ataques sofisticados (como *Living off the Land* y exfiltración de datos) basándose en su **error de reconstrucción (MSE)**.

---

## 1. Requisitos previos y configuración del entorno

Antes de ejecutar el script, asegúrese de tener instalado Python 3.8+ junto con las bibliotecas necesarias para computación científica, aprendizaje profundo (*deep learning*) y visualización.

### Instalación de dependencias
Ejecute el siguiente comando en su terminal para instalar todos los paquetes requeridos:

```bash
pip install torch numpy pandas scikit-learn matplotlib seaborn
```

*Nota: No se requiere GPU. La simulación se ejecuta extremadamente rápido (menos de 10 segundos) en una CPU estándar.*

---

## 2. Cómo ejecutar el script

Para ejecutar la simulación, navegue hasta el directorio donde se encuentra guardado `ueba-autoencoder-simulation.py` y ejecute:

```bash
python ueba-autoencoder-simulation.py
```

### ¿Qué sucede durante la ejecución?
1. **Generación de telemetría sintética**: El script modela **1.000 filas de referencia** de actividad diurna normal en 5 características (inicios de sesión, transferencias, creación de procesos, horas, actividad administrativa) junto con **15 escenarios de ataque avanzados de múltiples etapas** (LotL, exfiltración y abuso de privilegios administrativos).
2. **Entrenamiento del modelo**: Se inicializa un autoencoder subcompleto de PyTorch con 5 capas. Se entrena durante **200 épocas** *estrictamente* con los datos normalizados de comportamiento normal para aprender la línea base operativa habitual.
3. **Inferencia de anomalías**: El modelo evalúa el conjunto de pruebas completo. Calcula el **Error Cuadrático Medio (MSE)** entre las entradas originales y sus salidas reconstruidas.
4. **Generación de resultados visuales y analíticos**: El script calcula un umbral dinámico de anomalías (el percentil 99 de los datos normales) y exporta tanto un gráfico de dispersión de alto contraste como un informe tabular de métricas. ---

## 3. Resultados esperados y verificación

Tras una ejecución exitosa, la terminal mostrará lo siguiente:
```text
Simulation finished successfully!
Normal baseline median error: 0.2779
Anomalous median error: 588.1509
```

Además, el script genera dos archivos clave:

### A. Gráfico de visualización de anomalías (`reconstruction_error_chart.png`)
* **Qué muestra**: Un diagrama de dispersión que compara actividades normales frente a maliciosas en una escala logarítmica.
* **Indicador clave**: Las actividades normales se agruparán estrechamente por debajo de la línea roja discontinua (Umbral). Los ataques LotL, las exfiltraciones y los abusos de cuenta mostrarán picos verticales, generando **errores de reconstrucción entre 50 y 5000 veces mayores**.

### B. Resumen analítico (`ueba_simulation_summary.csv`)
Este archivo contiene la distribución estadística de los errores de reconstrucción en diferentes categorías:

| Tipo de actividad | Error mín. | Error mediano | Error máx. | % Anómalo |
| :--- | :--- | :--- | :--- | :--- |
| **Comportamiento normal** | ~0.001 | ~0.277 | ~5.440 | 1.0% |
| **Ataque LotL (Caso A)** | ~159.88 | ~588.15 | ~1261.16 | 100.0% |
| **Exfiltración de datos (Caso B)** | ~795.52 | ~1664.78 | ~5520.91 | 100.0% |
| **Abuso de privilegios de admin. (Caso C)** | ~76.85 | ~98.85 | ~436.50 | 100.0% |

## 4. Ajustes y experimentación (Desafíos rápidos)

El script es altamente personalizable. Abre el archivo de Python para intentar lo siguiente:
* **Ajustar el cuello de botella**: Localiza `latent_dim=2` en el script. Prueba a cambiarlo por `latent_dim=1` o `latent_dim=3` para observar cómo la modificación del cuello de botella de la red afecta a la precisión de la reconstrucción de la línea base normal. *
* **Haz que un ataque sea "sigiloso"**: Modifica los parámetros de la sección `# Case B: Quiet Data Exfiltration` reduciendo `data_anom_b` a un valor menor (por ejemplo, niveles diurnos estándar). Comprueba si el atacante puede eludir el umbral de anomalía de **1,76** sin ser detectado.
